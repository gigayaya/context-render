# claude-mod/

`ctxr-live`: Claude Code function-hooks plugin that draws `ctxr live --json` above the prompt. Presentation only — attribution and map geometry live in Python (`context_render/report/context_map.py`, `live.py`); never re-derive them here. Zero API calls: no `$.model.*`.

| name | topic | when to load |
|---|---|---|
| `.claude-plugin/plugin.json` | Manifest + `userConfig` (`command`, `debounceMs`, `layout`: `bottom` \| `sidebar`) | Adding options |
| `types/index.d.ts` | Snapshot types mirroring `ctxr live` JSON (incl. `vertical`) + `PluginState['ctxr-live']` (incl. sidebar `placement`) | Changing the JSON schema (bump both `SCHEMA_VERSION`s) |
| `hooks/core.ts` | Pure helpers: width, argv (`--height`), result parsing, timeline lines, band row filters (occupancy bar, number lanes), last-event names after the arrows; sidebar: `parseLayout`, `sidebarName` (15-char cleaned names), `nameRole`, `sidebarHeight`, `isSidebarActive` (band fallback rule) | Changing formatting, parsing or the sidebar rules |
| `hooks/scheduler.ts` | Debounce + single-flight (one ctxr process at a time) | Changing refresh timing |
| `hooks/view.tsx` | Pure trees: band, pane, sidebar map (`sidebarTree`) | Changing what is drawn |
| `hooks/register.tsx` | Wiring: session.start / tool.call / turn.complete / ui.render / `/ctx`; sidebar layout: `ctxr-map` pane, `/ctx-map`, placement state, band yields while the map is docked | Changing triggers |
| `tests/` | `claude plugin test claude-mod`; `sidebar.test.ts` covers the sidebar layout (pane lifecycle, band fallback, `--height`); `engine.ts` holds the bottom (engine) answers — calls on `$` answer `{ value }`, the test `$` has no `state` noun so `memState` stands in | — |
